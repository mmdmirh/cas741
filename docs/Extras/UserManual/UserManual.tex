\section{Introduction}

\progname{} is a browser-based exercise form-feedback tool. It uses
your webcam to estimate body pose, computes joint angles in real time,
and draws a skeleton plus a rep counter and a form-quality indicator
on top of the live video. This manual explains how to install and run
the reference implementation. It assumes you are comfortable with a
terminal but does not assume prior Python or Node.js experience.

\section{System Requirements}

\subsection{Hardware}

\begin{itemize}
  \item A computer with a built-in or USB webcam.
  \item At least 4~GB of free RAM.
  \item A fairly recent CPU. Apple~Silicon (M1 or newer), or any
    x86-64 CPU from the last five years, is enough.
  \item A display of at least $1280\times720$.
\end{itemize}

\subsection{Software}

\begin{itemize}
  \item Operating system: macOS~12 or newer, or a recent Linux
    (Ubuntu~22.04 or similar). Windows is expected to work but was
    not exercised during CAS~741 testing.
  \item Python~3.9 for the backend. Other Python~3 versions in the
    3.9--3.11 range are likely to work; 3.9.6 is the reference.
  \item Node.js~18 or newer for the frontend. Vite needs a recent
    Node.
  \item Redis is optional. Django Channels uses it for the WebSocket
    transport. The default configuration uses an in-memory channel
    layer, which does not need Redis for a single-process local run.
  \item A modern browser that supports \texttt{getUserMedia}: Chrome,
    Edge, Firefox, or Safari in their current versions.
\end{itemize}

\section{Installation}

\subsection{Obtain the source}

Clone the repository and check out the submodule that contains the
application code:

\begin{verbatim}
git clone --recursive https://github.com/mmdmirh/cas741
cd cas741/FitCoachAR
\end{verbatim}

If the repository was cloned without the \texttt{--recursive} flag,
initialise the submodule explicitly:

\begin{verbatim}
git submodule update --init --recursive
\end{verbatim}

\subsection{Backend}

From the \texttt{FitCoachAR/src/backend} directory:

\begin{verbatim}
cd src/backend
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
\end{verbatim}

The pinned dependencies include Django, Channels, MediaPipe (via the
\texttt{mediapipe-silicon} wheel on Apple~Silicon;
\texttt{mediapipe} on x86-64), NumPy, SciPy, and \texttt{pykalman}.

Apply the Django migrations:

\begin{verbatim}
python manage.py migrate
\end{verbatim}

\subsection{Frontend}

From the \texttt{FitCoachAR/src/frontend} directory, in a separate
terminal:

\begin{verbatim}
cd src/frontend
npm install
\end{verbatim}

\section{Running \progname}

\subsection{Start the backend}

From the \texttt{src/backend} directory, with the virtual environment
active:

\begin{verbatim}
python manage.py runserver
\end{verbatim}

The backend listens on \texttt{http://localhost:8000}. The WebSocket
endpoint used by the frontend is served on the same host.

\subsection{Start the frontend}

From the \texttt{src/frontend} directory:

\begin{verbatim}
npm run dev
\end{verbatim}

Vite prints the development URL (typically
\texttt{http://localhost:5173}). Open that URL in a supported browser.

\subsection{Grant camera permission}

The first time you open the app, the browser asks for permission to
use the webcam. Camera permission is required; the app cannot work
without it. If you denied permission earlier, re-enable it in the
browser's site-settings panel and reload the page.

\section{Using the Application}

\subsection{Select an exercise}

The sidebar lists the supported exercises (squat, bicep curl). Pick
one before starting a session. The selection is sent to the backend
and tells the state machine which validity rules to apply.

\subsection{Position the camera}

For best results:

\begin{itemize}
  \item Place the camera so your full body is in frame for squats, or
    so the relevant arm is clearly visible for bicep curls.
  \item Stand 2--3 metres back from the camera.
  \item Use a plain background and diffused lighting.
  \item Wear reasonably fitted clothing. Very loose clothing makes
    landmark tracking less accurate.
\end{itemize}

\subsection{Interpret the overlay}

The live view shows three things:

\begin{itemize}
  \item A skeleton overlay, drawn between the tracked body landmarks.
    A steady overlay means the pose backend is tracking you. A
    flickering overlay means partial occlusion or poor lighting.
  \item A rep counter, which is the number of valid reps done so far
    in the current session. It only goes up when both the
    range-of-motion and the timing constraint are satisfied.
  \item A short form-quality badge. Examples: ``Go deeper''
    (range of motion was incomplete), ``Too fast'' (rep was
    shorter than $t_{\min}$).
\end{itemize}

\subsection{Ending a session}

Close the browser tab or click the ``End session'' control in the
sidebar. The WebSocket closes cleanly; no logout is needed.

\section{Uninstallation}

To remove \progname{} from the machine:

\begin{enumerate}
  \item Stop the backend and frontend processes
    (\texttt{Ctrl+C} in each terminal).
  \item Deactivate and delete the backend virtual environment:
    \begin{verbatim}
deactivate
rm -rf src/backend/venv
    \end{verbatim}
  \item Delete the frontend dependency cache:
    \begin{verbatim}
rm -rf src/frontend/node_modules
    \end{verbatim}
  \item Delete the cloned repository itself if no longer needed:
    \begin{verbatim}
cd ../../../..
rm -rf cas741
    \end{verbatim}
\end{enumerate}

No system-level packages are installed by \progname{}, so no
system-wide cleanup is required.
